## 2. 测试方法

- 数据：固定种子（20261123）生成，时间戳单调递增、跨度 7 天，中英文混合消息（提取进度/校验/损坏文件/英文 chunk），级别 INFO/WARN/ERROR 混合。
- 量级：1,000 / 5,000（应用真实环形容量上限）/ 10,000 / 100,000 / 1,000,000 条。
- 计时：每阶段 1 次预热 + N 次计时取平均（≤10k：20 次；100k：5 次；1M：3 次）；阶段间强制 GC 清理。
- 分配量：`GC.GetAllocatedBytesForCurrentThread` 差值 / 迭代次数。
- 阶段口径：
  - **Filter**：旧 = lock + LINQ Where.ToList；新 = 二分快路径 + 预分配。范围分"全部"与"最近 24 小时（约 1/7 命中）"。
  - **Format**：全量条目 → 完整 .log 字符串（预览路径）。
  - **导出核心（格式化+写入）**：旧 = 生成巨串 + 1KB 缓冲 StreamWriter.Write；新 = 64KB 缓冲 StreamWriter + WriteTo 流式。同口径对比。
  - **端到端**：筛选（全部范围）+ 格式化 + 写入 MemoryStream（模拟 SAF 输出流）。
- **正确性门禁**：每档先比对新旧完整管线输出字节，不一致立即失败。

## 5. 结论

1. **速度**：数据量越大收益越显著——10k 条端到端 1.7x、100k 条 1.7x、1M 条 1.8x（293ms → 161ms）；范围筛选（最近 24 小时）提速 6.9x–26.7x。
2. **内存**：端到端分配量 10k 降 66%、100k 降 73%、1M 降 77%（681MB → 153MB）；导出不再驻留全文巨串，GC 压力与 OOM 风险大幅下降。
3. **响应性**：写入完全移出 UI 线程（后台 Task + 64KB 缓冲流式写 SAF），大日志导出不再阻塞界面——这是真机体验上最直接的改善（基准为纯 CPU 口径，未计入旧实现的主线程阻塞代价）。
4. **正确性**：5 档数据量新旧输出字节级一致；74/74 测试通过；格式契约（头部、时间戳格式、行格式、换行、UTF-8 无 BOM）完全保持。
